# Архитектура

Сервис по одной фотографии этикетки возвращает одну карточку каталога «Своё Вино».
Offline-часть готовит каталог и индексы, online-часть распознаёт фото за ~1,5 с на CPU.
Все артефакты версионируются checksum-ами; несовместимый индекс отклоняется при старте.

```text
 OFFLINE                                                     ONLINE (services/inference)
 ───────                                                     ──────────────────────────
 Датасет/ CSV + RAR ─┐                                       фото ──► decode, EXIF, лимиты (imaging.py)
 vino-svoe.ru snap ──┴► catalog merge ──► 2 182 вина                     │
                         │ (scripts/)                        ┌──────────┴───────────┐
                         ├──► SigLIP 2 ONNX gallery ────────►│ SigLIP 2: 2 вида фото│  PP-OCRv5 (параллельно)
                         │    (2 вида на вино)               │ × 2 вида эталона     │  слова + позиция + размер
                         ├──► RootSIFT index ──┐             └──────────┬───────────┘           │
                         │                     │             top-30 визуально ∪ top-10 по тексту ◄┘
 field-like рендеры ─────┴► fusion.json ◄──────┤                        │
 (evaluation/)              (conditional logit)└──────────► RootSIFT + RANSAC по shortlist
                                                                        │
                                                          18 признаков на кандидата ─► softmax
                                                                        │
                                              /v1/eval/predict {"slug"}  /v1/search top-5, p, margin
                                                                        │
                                              apps/web: карточка · «Это одно из них?» · «Нет в каталоге»
                                                        · цифровой сомелье · аналоги других виноделен
```

## 1. Данные (`scripts/`)

- `build_catalog.py` — чистит CSV организатора (4 147 строк → 2 103 уникальных slug),
  сохраняет provenance строк и отделяет неоднозначные фотографии.
- `extract_catalog_media.py` — извлекает эталонные фото из multipart RAR без полной распаковки, с проверкой CRC.
- `scrape_wine_catalog.py` + `merge_wine_catalog.py` — публичный снапшот vino-svoe.ru
  (каталог пополняется ~50 вин в день). Снапшот 27.09.2026 добавил 79 карточек,
  итог — **2 182 вина, 2 111 с однозначным эталоном**. Slug-и организатора неизменны.
- `build_artifacts.sh` — одна команда, пересобирающая все индексы из `Датасет/`.

## 2. Нормализация фото (`imaging.py`, `views.py`)

Определение формата по байтам, EXIF-поворот, alpha → белый фон, лимиты размера.
Эталоны каталога — студийные снимки бутылки целиком, а полевые фото — крупный план
этикетки. Поэтому обе стороны кодируются несколькими видами:

| сторона | виды |
| --- | --- |
| эталон | бутылка, вырезанная с фона (`bottle`), и полоса этикетки (`label`) |
| запрос | весь кадр (`full`) и центральный кроп 80%×60% (`centre`) — цель в кадре по центру |

Сравниваются все пары видов; это главный приём нормализации масштаба.

## 3. Признаки

| канал | модуль | что даёт |
| --- | --- | --- |
| SigLIP 2 base/16-256 (ONNX, CPU) + линейный адаптер студия→полка | `encoder.py` | глобальное сходство, shortlist top-30; Recall@30 = 100% на field-v1 |
| PP-OCRv5 mobile, East-Slavic recognizer | `label_text.py` | слова с весом по центральности и размеру; цвет и сладость — голосованием слов с этим весом, чтобы текст соседних бутылок не перебивал центральную |
| Текстовый матчинг | `label_text.py` | IDF по названию/винодельне/сорту, fuzzy-токены, латиница↔кириллица, склейки, стиль и винтаж |
| RootSIFT + RANSAC | `local_features.py` | число геометрических inliers для кандидатов shortlist |

OCR-нормализация учитывает реальные ошибки распознавания: латинские и греческие
двойники кириллицы (`MACCAHAPA`, `ΑЛΥШТА`), смешанный алфавит (`АРАТTИ`), склеенные слова (`ПИНОНУАР`),
цифры в словах (`KPACHOE2022`), римские числа (`XXIV` → 24) и запись сортов латиницей
(`CABERNET FRANC` ↔ «Каберне Фран»).

## 4. Поиск и слияние (`pipeline.py`)

1. SigLIP оценивает весь каталог (матричное умножение, 2 111 × 768, <5 мс).
2. Shortlist = top-30 визуально ∪ top-10 по тексту.
3. RootSIFT проверяет геометрию только для shortlist (быстрее и точнее полного голосования).
4. Для каждого кандидата — 18 признаков: визуальные сходства и разрыв с лучшим,
   inliers, текстовый балл, покрытие, конфликт/совпадение стиля (сухое/брют/…)
   и винтажа, доля слов этикетки, которые объясняет соперник, но не этот кандидат.
5. Conditional-logit (softmax по кандидатам), обученный на field-like фото
   (`training/fit_fusion.py`), даёт вероятности. Веса — `services/inference/data/fusion.json`.

Адаптер SigLIP (`training/fit_adapter.py`) — матрица 768×768 с сильной регуляризацией
к единичной (l2 = 20): на винах, не участвовавших в обучении, Top-1 визуального канала
растёт с 71% до 84%, а на реальном фото Массандры правильное вино поднимается с 14-го
на 10-е место (без регуляризации — падает на 26-е, поэтому она и выбрана).

При обучении ранкера в 20% примеров визуальные и геометрические признаки правильного
вина меняются местами с признаками соседа по серии («эталон не совпадает с этикеткой
на полке»: новый винтаж, редизайн, крошечное фото в каталоге). Без этого ранкер в таком
случае ошибается уверенно (точность 2% при p ≥ 0,8), с ним — чаще говорит «не уверен»
и опирается на текст. Реальные фото из публичного набора подтверждают выбор.

Вероятность top-1 — это `confidence`; `top1_top2_margin` — разрыв с вторым местом;
`confidence_top5` — масса вероятности top-5.

## 5. Уверенность и «нет в каталоге»

- `not_found`: отдельная логистическая модель «есть ли вино в каталоге» по абсолютным
  признакам лучшего кандидата (p(top-1), inliers RootSIFT, визуальное сходство,
  покрытие текста). Softmax относителен и остаётся высоким у импортного вина, которое
  просто сильнее слабых кандидатов; абсолютные признаки — нет. Негативы — реальные фото
  вин не из каталога, валидация leave-one-out (`training/fit_open_set.py`). Порог
  выбран так, чтобы ни одно реальное вино из каталога не получило «нет в каталоге».
- `found`: p(top-1) ≥ 0,80 — сразу одна карточка, без экрана выбора;
- `uncertain`: карточка + «Это одно из них?» с вероятностями близких вариантов серии.

Evaluator-маршрут `/v1/eval/predict` всегда отдаёт лучший slug; при любой ошибке
fusion-ветки срабатывает прежний каскад (RootSIFT/visual/OCR), а не HTTP 500.

## 6. Цифровой сомелье и аналоги (`sommelier.py`, `analogs.py`)

Три вопроса (повод → блюдо → вкус) → вердикт, температура подачи, бокал, с чем ещё
сочетать и вина каталога, которые подходят к блюду лучше, но близки по стилю.
«Аналоги других виноделен» ранжируются по цвету, сладости, пересечению сортов,
региону и визуальному сходству этикетки, с объяснением причин. Всё выводится только
из полей каталога — рейтинги и награды не придумываются.

## 7. Веб (`apps/web`)

Mobile-first React (vinext), шрифты и палитра портала «Своё Вино» (Playfair Display,
#8f3d42). Состояния: сканер → загрузка → карточка / «Это одно из них?» / «Нет в каталоге» /
ошибка. История сохраняется только в браузере; фото не сохраняются ни клиентом, ни API.

## 8. Оценка (`evaluation/`)

| field-v1, 700 фото | Top-1 / micro-F1 | Macro-F1 | Top-5 | p50 / p95 |
| --- | ---: | ---: | ---: | ---: |
| прежний каскад | 0,660 | — | 0,660 | 0,29 / 1,30 с |
| текущий пайплайн | 0,933 | 0,890 | 0,996 | 1,2 с (p50) |

Реальные фото из супермаркета (84 снимка, 17 вин из каталога) — [docs/REAL_PHOTO_TEST.md](docs/REAL_PHOTO_TEST.md):
top-1 82%, top-5 94%, все ответы «найдено» верны, ни одно вино из каталога не отклонено;
46% вин не из каталога честно получают «нет в каталоге».


Публичный набор — 3 фото без ответов, два из которых отсутствуют в каталоге.
Поэтому качество измеряется на field-like наборе: `field_benchmark.py` рендерит
эталон в крупный план у полки — цилиндрический изгиб этикетки, перспектива, соседние
бутылки, блики, баланс белого, размытие, шум, JPEG. field-v2 (1 500 фото) используется
для обучения fusion, field-v1 (700 фото) — только для оценки.

## 9. Границы отказа

| сбой | поведение |
| --- | --- |
| битое / огромное изображение | быстрый структурированный JSON-ответ об ошибке |
| нет SigLIP/OCR артефактов | прежний каскад RootSIFT/visual/Tesseract |
| исключение в fusion | fallback-каскад, evaluator всё равно получает slug |
| неизвестный slug в сомелье | 404, без выдуманной рекомендации |
| UI не достучался до API | preview сохраняется, предлагается повтор |
